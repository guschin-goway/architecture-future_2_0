# Обоснование инфраструктуры (Yandex Cloud + Terraform)

## 1. Почему Yandex Cloud

- Локализация данных в РФ (важно для медицины и финтеха)
- Соответствие требованиям регуляторов
- Поддержка VPC и изолированных подсетей

---

## 2. Архитектурные решения

### Разделение на public и private subnet

Public:
- Bastion Host

Private:
- Application Server
- Data Node

Это снижает риск несанкционированного доступа.

---

## 3. Размеры виртуальных машин

Bastion:
2 CPU / 2 GB — минимальная нагрузка.

Application Server:
4 CPU / 4 GB — API и бизнес-логика.

Data Node:
4 CPU / 8 GB — подготовка аналитики и heavy workload.

---

## 4. Почему Terraform

Декларативный подход позволяет:

- воспроизводить инфраструктуру
- версионировать её в Git
- быстро масштабировать
- создавать dev/test/prod среды

---

## 5. Связь с бизнес-целями

| Цель                              | Решение                   |
|-----------------------------------|---------------------------|
| Безопасность медицинских данных   | Private subnet            |
| Масштабирование аналитики         | Data VM с увеличенной RAM |
| Быстрое подключение новых доменов | IaC + модульная структура |
| Соответствие регуляторам          | Размещение в РФ           |

---

## Итог

Инфраструктура:
- масштабируемая
- изолированная
- воспроизводимая
- соответствующая регуляторике

Поддерживает стратегию перехода в облако и доменную архитектуру Future 2.0.
