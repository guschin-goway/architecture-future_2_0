# Task1 - Анализ проблем и приоритизация

## 1. Ключевые бизнес-сценарии

1. Быстрая подготовка управленческой отчётности
2. Независимое развитие финтех-направления
3. Независимое развитие ИИ-направления
4. Подключение новых бизнесов
5. Соблюдение требований регуляторов
6. Снижение time-to-market новых продуктов

---

## 2. Проблемные места текущей архитектуры

| №  | Проблема                                          | Какой сценарий страдает | Бизнес-эффект                               |
|----|---------------------------------------------------|-------------------------|---------------------------------------------|
| P1 | Монолитный DWH с бизнес-логикой                   | 2,3,4,6                 | Любое изменение затрагивает все направления |
| P2 | SQL Server 2008 (legacy)                          | 1,4                     | Ограничение масштабирования                 |
| P3 | Большое количество трансформаций в DWH            | 1                       | Отчёты строятся часами                      |
| P4 | ESB как центральная точка интеграции              | 2,3,4                   | Сложность подключения новых сервисов        |
| P5 | Отсутствие доменной ответственности за данные     | 2,3,4                   | Нет data ownership                          |
| P6 | BI жёстко связан с DWH                            | 1                       | Низкая гибкость аналитики                   |
| P7 | Медицинские и финансовые данные в одном хранилище | 5                       | Регуляторные риски                          |
| P8 | Отсутствие событийной архитектуры                 | 4,6                     | Медленный вывод новых продуктов             |

---

## 3. Приоритизация (MoSCoW)

### Критично для выручки и устойчивости

| Проблема | Обоснование                                |
|----------|--------------------------------------------|
| P1       | Блокирует независимое развитие направлений |
| P3       | Замедляет управленческие решения           |
| P7       | Риск штрафов и потери лицензии             |
| P8       | Ограничивает масштабирование               |
| P2       | Технологический риск и ограничение роста   |

Связь с целями:
- Ускорение отчётности
- Снижение регуляторных рисков
- Рост выручки через быстрый запуск продуктов

---

### Высокий приоритет

| Проблема | Обоснование                         |
|----------|-------------------------------------|
| P4       | Упрощение интеграций                |
| P5       | Повышение ответственности за данные |
| P6       | Улучшение self-service аналитики    |

---

### Средний приоритет, может подождать

- Полная замена BI-инструмента
- Полная миграция legacy-интерфейсов

---

### Низкий приоритет, может подождать более 1 года

- Полная переработка всех исторических данных
- Полный отказ от legacy во всех доменах

## 5. Ожидаемый эффект через год

- Отчёты формируются за минуты вместо часов
- Домены развиваются независимо
- Новые бизнес-направления подключаются через события
- Медицинские данные изолированы от аналитической витрины
- Снижен регуляторный риск
