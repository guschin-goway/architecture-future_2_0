# Task3 - Технологический радар и Roadmap трансформации

---

# 1. Обоснование технологического радара

## ADOPT (внедрять активно)

### Cloud Infrastructure
Поддерживает:
- Масштабирование аналитики
- Подключение новых бизнесов
- Отказоустойчивость

Бизнес-эффект:
- Снижение затрат на железо
- Повышение доступности сервисов

---

### Event Streaming (Kafka / PubSub)
Поддерживает:
- Независимость доменов
- Интеграцию финтеха, ИИ и партнёров

Бизнес-эффект:
- Быстрый вывод новых продуктов
- Устранение зависимости от DWH

---

### Data Mesh
Поддерживает:
- Domain ownership
- Независимое развитие направлений

Бизнес-эффект:
- Ускорение time-to-market
- Прозрачная ответственность за данные

---

### Lakehouse
Поддерживает:
- Быструю отчётность
- Большие объёмы данных

Бизнес-эффект:
- Отчёты строятся за минуты, а не часы

---

### Semantic Layer
Поддерживает:
- Self-service BI
- Единые метрики

Бизнес-эффект:
- Быстрое принятие управленческих решений

---

## HOLD (вывод из эксплуатации)

- Ограничение масштабирования
- Рост техдолга

# 2. Roadmap (12 месяцев)

---

## Этап 1 (0–3 месяца)
Цель: Подготовка архитектурной основы

### Действия:
- Развёртывание Cloud Infrastructure
- Запуск Event Streaming Platform
- Выделение доменов
- Настройка IAM и RBAC

### Результат:
- Архитектура готова к доменной модели
- Устранена централизация через ESB

### Ответственные:
- Архитектурная команда
- DevOps
- Security

Бизнес-эффект:
- Снижение регуляторных рисков
- Основа для масштабирования

---

## Этап 2 (3–6 месяцев)
Цель: Запуск Data Platform

### Действия:
- Развёртывание Lakehouse
- Настройка потоковой загрузки данных
- Формирование первых data products (финансы, продажи)

### Результат:
- Отчётность работает вне legacy DWH
- Снижение нагрузки на старую систему

### Ответственные:
- Data Engineering
- BI команда

Бизнес-эффект:
- Ускорение управленческой отчётности
- Повышение прозрачности данных

---

## Этап 3 (6–9 месяцев)
Цель: Запуск портала самообслуживания

### Действия:
- Внедрение Semantic Layer
- Разработка Self-Service портала
- Обучение бизнес-пользователей

### Результат:
- Бизнес строит отчёты самостоятельно
- Снижение нагрузки на IT

### Ответственные:
- BI команда
- Product team
- HR (обучение)

Бизнес-эффект:
- Быстрое принятие решений
- Сокращение time-to-insight

---

## Этап 4 (9–12 месяцев)
Цель: Масштабирование и партнёрская экосистема

### Действия:
- Подключение фарм-компаний
- Подключение производителя медоборудования
- Пилот Data Quality Framework
- Частичный вывод SQL Server 2008

### Результат:
- Экосистема готова к расширению
- DWH перестаёт быть центром архитектуры

### Ответственные:
- Integration team
- Data Governance
- Архитекторы

Бизнес-эффект:
- Рост выручки через новые направления
- Гибкость масштабирования

---

# 3. Ключевые метрики успеха

- Время формирования отчёта < 5 минут
- Time-to-market нового сервиса < 3 месяца
- 80% отчётов создаются через self-service
- Отсутствие регуляторных нарушений
- Снижение затрат на инфраструктуру

---

# 4. Итоговое состояние через год

- DWH перестаёт быть центром всей логики
- Домены развиваются независимо
- Self-service портал работает
- Cloud обеспечивает масштабирование
- Компания готова к экосистемному росту
